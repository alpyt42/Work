# Tools

Reusable scripts of the workspace, organized by domain. Every command runs from the root of `Work/` with `uv run`. The scripts find the root of `Work/` from their own location (`WORK_DIR` and `BRAIN_DIR` variables to point elsewhere).

Shared local configuration, ignored by Git, which stays at the root of this folder: `.env` (optional tokens, created from [.env.example](.env.example); no shipped tool needs one for now). Never read, copy or cite it.

## Memory (brains)

The tools act on the default brain, or on another brain with `BRAIN_DIR` (`--brain PATH` for `action.py`, `decision.py` and `timeline.py`); `new-brain.py`, `brain-state.py` and `check-links.py` also know the `brain-<name>` brains, and the `brain-state.py` commands below read every brain unless `--brain <name>` keeps one. The default brain is the one named by `"defaultBrain"` in the ignored `work-config.local.json`, else `brain/`, else the only brain at the root (`uv run tools/machine/work_config.py default-brain`); it is what lets the default brain folder be renamed, for example `brain-<name>`.

| Command | Role | Guide |
|---|---|---|
| `uv run tools/brain/new-brain.py <folder> [--scope S] [--description D] [--remote PATTERN] [--email PATTERN] [--no-git]` | Creates a blank brain (`brain` or `brain-<name>`) from `kit/brain/seed/`: refuses to overwrite an existing folder, runs `git init` (unless `--no-git`), with no commit and no remote. The four options fill in the brain's boundary in `.data/brain.json` | script header |
| `uv run tools/brain/check-links.py [--allow-missing-local]` | Checks that every Markdown link of a brain points to an existing file; a link to another brain fails even if the target exists; `--allow-missing-local` reports separately the targets missing from `artifacts/` and `repos/`; the templates in `skills/<name>/assets/` are not checked | script header |
| `uv run tools/brain/brain-state.py map [--json] [--brain <name>] [--archived \| --all]` | Map of every brain in one glance: one line per project with its page, register prefix, actions by state, overdue actions, proposed decisions and last timeline entry; the first stop to find where to work. Archived projects are hidden and counted; `--archived` shows only them, `--all` both | script header |
| `uv run tools/brain/brain-state.py brief <project> [--brain <name>] [--words N] [--limit N] [--decisions N] [--archived] [--json]` | Briefing of one project in about 40 lines, to load at the start of a task instead of its pages and registers: the page's `## Current state` section, else its first summary section (`## Summary`, `## En bref`, `## Context`; the output says which), cut after 150 words; action and decision counts; late then other open actions, one line each (10 at most); proposed and accepted decisions, most recent first (5 at most); the five latest timeline entries; one `Repos:` line from the brain's catalog `.data/client-repos.json` (how many repositories, the names of those present on this machine, how many missing, and the `client-repos.py list --project` command; left out when the catalog names none); then at most four commands that load one part of the project, never a whole file: the outline of its page, its open actions, its decisions and the latest index of its sources (`--brain` added for `action.py` and `decision.py` outside the default brain). `<project>` is named as for `action.py list --project`, or by the two short names `map` prints: the project folder name or the register ID prefix; an unknown or ambiguous name lists the candidates; an archived project only with `--archived` | script header |
| `uv run tools/brain/brain-state.py due [--days N] [--brain <name>] [--json]` | Late actions and actions due within N days (default 7) of every brain, one line each, by project, late first | script header |
| `uv run tools/brain/brain-state.py changes --since <YYYY-MM-DD\|Nd> [--project P] [--limit N] [--brain <name>] [--json]` | What changed since a day or N days ago, by project, newest first: timeline entries (page and `journal/`), actions created or closed (live register and yearly archives), decisions dated or settled; read from the dates written in the files, without Git. With `--project`, every event of the period; otherwise 20 events per project (`--limit`), cut by whole days, most recent first, then a `+N more` line with the dates left and the `--project` command that shows them | script header |
| `uv run tools/brain/brain-state.py find <term> [--project P] [--in KIND[,KIND]] [--per-file N] [--limit N] [--archived \| --all] [--brain <name>] [--json]` | Searches a literal piece of text, without case or accents, in every Markdown file of the brains but `skills/` and the hidden folders, or of one project folder with `--project`: action lines and their sub-bullets (source, history), decisions (title and body), project and client pages, glossaries, people, workstreams, notes, journals and dated sources. Each file once, `kind  path`, then its hits indented, `:line  excerpt`: 160 characters at most, centred on the match. In a register, one hit per action or decision, starting with its `ID [state]` or `no. N [state]`: its first line when it matches, else its first matching sub-bullet; the actions and decisions whose title matches come first. Order of the files: `action`, `decision`, `page`, `person`, `workstream`, `note`, `journal`, `source`, journals and sources most recent first. 1 hit per file (`--per-file`, the last one ends with `(+N in this file)`), 40 in all (`--limit`), then one line counting what is left by kind; `--in` keeps some kinds; `--json` adds the counts by kind. the action archives and the other `archive/` folders are read with `--all`, and on their own when nothing else matches; the archived projects never are: `--archived` searches them alone, `--all` everything, and `no match` counts the archived projects left out | script header |
| `uv run tools/brain/brain-state.py section <file>[:line] [heading] [--words N] [--brain <name>] [--json]` | One part of a Markdown page of a brain instead of the whole file. `<file>` is the path that `find` and `brief` print (from a brain with `--brain` too); a file outside the brains is refused. Alone: the outline (front matter, one line per heading with its line number and the words of its section, total words). `<file>:<line>`: 150 words (`--words`) of the section that holds that line, around it. `<file> <heading>`: the section with that title, else whose title starts with it, else contains it, without case or accents; `summary` stands for the first of Summary, Résumé, En bref, Current state, État actuel; several matches are listed (exit code 1). The section runs to the next heading of the same or a higher level and is cut after 400 words (`--words`) with `(truncated, N more words: path:line)` | script header |
| `uv run tools/brain/brain-state.py person <name> [--words N] [--limit N] [--brain <name>] [--json]` | Who someone is and what they carry: the identity part of their `people/` page (name, role, organization, aliases, missions, the lines under the title, the `Role and scope` section; 120 words at most), their open actions in every brain, one line each (ID, state, due date, title, project; 10 at most), then the page path. `<name>` is the slug of the page, or words of the name or of one alias, without case or accents; several pages are listed, an unknown name gets the closest ones (exit code 1). An owner counts when it is the full name, an alias, or a first name that one person only bears; a first name shared by several people pages is listed apart, with the people it may stand for. The owner of a brain (`owner` in `.data/doctor.json`) counts as one more person | script header |
| `uv run tools/brain/brain-state.py archive\|unarchive <project> [--write] [--brain <name>] [--json]` | Archives a finished project, or a whole client (`clients/<client>`), into the `archive/` folder at its level: a client mission to `projects/clients/<client>/missions/archive/<mission>/`, an internal project to `projects/internal/archive/<project>/`, a client to `projects/clients/archive/<client>/` with its missions; rewrites the Markdown links into the folder and, one level deeper, those inside it that point out, then runs the link check; a dry run unless `--write`. Refuses while an action is still to do, in progress or waiting. Files a project of the earlier places (`projects/archive/`, `projects/clients/<client>/archive/`) in the new ones. `unarchive` is the exact inverse. An archived project leaves the context of every command and of the web interface | script header |
| `uv run tools/brain/brain-state.py brains` | Lists the brains present (the default brain first) with their `scope`, their `description` and the transcripts they track | script header |
| `uv run tools/brain/brain-state.py transcripts [--new \| --where <file>]` | Merges the transcript states of every brain; `--new`: those that no brain tracks; `--where`: the brain that owns a file | script header |
| `uv run tools/brain/action.py board` | Prints the action registers by project in the terminal (`--write` for a Markdown preview, `--watch` to keep it up to date) | [action.md](brain/action.md) |
| `uv run tools/brain/action.py <command>` | Creates, reads, edits, completes the history of and deletes actions (agents and tasks-web), files the registers by status (`sweep`) and archives closures older than 30 days (`archive`); `list` filters by `--project`, `--state`, `--owner`, `--due-before YYYY-MM-DD` (due strictly before, earliest first) and `--limit N`, and prints one line per action with `--table`; `list`, `board`, `sweep`, `archive` and `check` leave the archived projects out (`--archived` on `list` and `check`), and every write refuses their actions; `show <ID> --text [--last N]` prints one action as compact text instead of JSON (its line, its dates, its source, the last 3 history entries, `file:line`); history entries hold 35 words at most | [action.md](brain/action.md) |
| `uv run tools/brain/action.py subtask add\|toggle\|edit\|remove\|move <ID> …` | Edits an action's checklist (15 words per subtask, 10 subtasks at most); refreshes `updated:` and adds no history; `list --table`, `board` and `show --text` show the progress `d/t` | [action.md](brain/action.md) |
| `uv run tools/brain/decision.py <command>` | Lists, proposes, accepts, rejects or supersedes the decisions of the `state/decisions.md` registers; `list` filters by `--project` and `--state proposed\|accepted\|rejected` (earlier name: `--status`), prints one line per decision with `--table` and leaves the archived projects out (`--archived`); `show <ref> --project P --text` prints one decision as compact text instead of JSON (number, state, date, title, its fields, `file:line`); `propose` holds 70 words at most for title, context, decision and consequences | [decision.md](brain/decision.md) |
| `uv run tools/brain/timeline.py add\|roll` | Writes a dated entry in the `## Timeline` of a project page (`add`), and moves the entries of past months into `journal/YYYY-MM.md` (`roll`, dry run unless `--write`) | [timeline.md](brain/timeline.md) |
| `uv run tools/brain/migrate-english.py [--brain PATH] [--diff] [--write \| --check \| --mapping]` | Converts a brain written with the earlier French format to the English structure, without touching written content: registers, template headings, front matter and header labels of pages, sources and person pages, tags of minutes, boilerplate lines, `tasks.md` and `.data` values. A line that mixes boilerplate with content is listed, not changed, and the brain's instruction files are translated by hand. Dry run by default, `--write` applies (refusing files with uncommitted changes), `--check` exits with code 1 if something is left to convert, `--mapping` prints the French-to-English table (`exact` or `judged`) | script header |

## Local interface (`tasks-web/`)

| Command | Role | Guide |
|---|---|---|
| `uv run tools/tasks-web/tasks-web.py [--port N] [--brain DIR]` | Local web interface for actions (Today, Actions, Board, Timeline, Docs, Tools, Sync, and one global search of the actions and the documents) on `http://127.0.0.1:8765/`; a selector at the top left switches between the brains of the workspace without a restart (`?brain=<name>`, `GET /api/brains`; `--brain` sets the default brain); the Tools view runs predefined commands (links, brains, transcripts, actions, repositories); the Sync view saves and sends the changed notes of each brain (one card per brain, a confirmation, then `git add -A`, `git commit` and `git push` of that brain only, every hook running) | [README.md](tasks-web/README.md) |
| `uv run tools/tasks-web/install-app.py [--dry-run] [--uninstall]` | Installs the "Actions Brain" launcher of this system: the macOS app in the artifacts folder (`--replace` moves an existing one to `archive/` first, nothing is overwritten), a Windows Start Menu shortcut (`--desktop` adds one on the Desktop) or a Linux applications menu entry; `--uninstall` removes only what it wrote | [README.md](tasks-web/README.md) |
| `uv run --script tools/tasks-web/launch.py` | Launcher run by those entries (macOS, Windows, Linux): opens the page, starting the server on port 8765 first when needed (log and PID in `agents/`), refuses when another program holds the port | [README.md](tasks-web/README.md) |
| `uv run tools/tasks-web/make-icon.py` | Writes the app icon into `tasks-web/static/` (SVG, PNG, ICO, ICNS) | [README.md](tasks-web/README.md) |
| `./tools/tasks-web/build-dock-app.sh`, `tools/tasks-web/launcher.sh` | Kept for macOS: the first runs `install-app.py --platform macos`, the second (called by apps built before it) runs `launch.py` | [README.md](tasks-web/README.md) |

## Repositories (`repos/`)

| Command | Role | Guide |
|---|---|---|
| `uv run tools/repos/client-repos.py list [<client> \| repos/<client>/<repo>]` | Lists the repositories of the private catalog `.data/client-repos.json` of the default brain; `--project P` keeps one project's, with `present` or `missing` on this machine | [README.md](repos/README.md) |
| `uv run tools/repos/client-repos.py status [--project P] [--json]` | Local state of the repositories present (branch, changes, ahead/behind, last commit) and Git roots under `repos/` missing from the catalog; `list` also takes `--project`, `--present`, `--missing`, `--json` | [README.md](repos/README.md) |
| `uv run tools/repos/client-repos.py check [<client> \| repos/<client>/<repo>]` | Compares the clones present with the catalog (`origin` URL) and shows the effective author and key of each one, without network | script header |

| `uv run tools/machine/doctor.py` | Read-only local diagnosis of the workspace, the brains and their boundaries | [README.md](machine/README.md) |

| `uv run tools/machine/preflight-push.py [--repo DIR] [REMOTE]` | Identity, SSH account, `brain.json` boundary and fast-forward checks before a push; run by the `pre-push` hook of Work and of every brain | [GIT-IDENTITY.md](machine/GIT-IDENTITY.md) |
| `tools/machine/hooks/claude-bash-guard.py` | Claude Code hook (`.claude/settings.json`): refuses direct `python`, deletions or moves out of the artifacts folder (`artifacts/`, or the folder set by `artifactsDir`), and Git hook bypasses | [README.md](machine/README.md) |
