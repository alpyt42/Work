# tools/machine/

Scripts that install and check the `Work/` workspace on a machine. They never modify the home configuration (`~/.gitconfig`, `~/.ssh/`) and never commit or push anything. Run them from the `Work/` root (`WORK_DIR` to target another workspace).

| File | Role |
|---|---|
| `install.sh [--brain URL] [--brain-perso URL\|new] [--no-bootstrap]` | Entry point after cloning `Work`: clones the private brain (`--brain <url>`) or creates a blank one from `kit/brain/seed/` (`tools/brain/new-brain.py`), optionally `brain-perso/` (`--brain-perso <url\|new>`), renames the Work-Starter remote to `starter`, then runs `bootstrap.sh` (unless `--no-bootstrap`). Safe to rerun: nothing is overwritten. The other brains (`brain-<name>`) are created with `new-brain.py` or cloned by hand. |
| `bootstrap.sh` | Prepares a fresh checkout: clones `brain/` from `BRAIN_REMOTE` (required) only when the workspace has no brain at all, installs the Git hooks in Work and in every brain present, creates `repos/` and `agents/` and the artifacts folder (`artifactsDir`, default `artifacts/`; see `work_config.py`), then validates the configuration, writes the lock, installs the third-party skills (`npx`, only if there are any), exposes the skills, checks the links and records the configuration fingerprint. Rerun it after adding a brain to install its hooks. |
| `update.sh` | Redoes the skills part of `bootstrap.sh` (validation, lock, installation of third-party skills, copies, links, link check, fingerprint), then reports the Git state of Work and of every brain (branch, unpushed commits), without pull, commit or push. Run it after a `git pull` of Work or of a brain that changes the configuration. |
| `work_config.py <command>` | Resolves the skill configuration: public defaults (`work-config.example.json`), then the `.data/work-config.json` of each brain, then the ignored `work-config.local.json` (the last layer wins; disabled names add up). Commands: `check` (validates), `list-brains` (the default brain first), `default-brain` (prints the folder name of the default brain, nothing and exit code 1 when there is none), `artifacts-dir [--check]` (prints the absolute path of the artifacts folder; `--check` also verifies that it exists and says whether it lies inside the Work root and, if not, whether `artifacts/` is a symlink to it), `list-own` (name, brain, `link` or `copy`), `list-third-party` (enabled ones), `list-catalog` (every known third-party skill), `lock` (writes `skills-lock.json`, refuses if it lists skills that no layer knows), `adopt [--brain B]` (records those skills in the `.data/work-config.json` of brain B, the default brain by default), `stamp` (writes `.work-state.json`), `status` (exit code 1 if the configuration changed since the last `stamp`). The default brain is `"defaultBrain"` in `work-config.local.json` (accepted in that layer only), else `brain/`, else the only brain at the root: `default_brain(root)` is the single implementation, reused by the other tools. The artifacts folder is `"artifactsDir"` in `work-config.local.json` (that layer only; an absolute path, or relative to the Work root, `~` expanded; `check` fails when it does not exist or is not a directory), else `artifacts/` at the Work root: `artifacts_dir(root)` is the single implementation, reused by `doctor.py`, `bootstrap.sh` and the Bash guard hook. To move the folder, for example into a synced cloud folder, move it yourself and set the key. |
| `link-skills.sh` | Exposes the enabled skills to the agents: links from `.agents/skills/` and `.claude/skills/` to `<brain>/skills/<name>`, links from `.claude/skills/` to the third-party skills installed in `.agents/skills/`; removes managed links that are no longer needed (including the old `../../skills/<name>` links, replaced by the new ones) and sets aside (`.agents/skills-disabled/`) the disabled third-party skills: a copy already set aside is replaced, and a re-enabled third-party skill is put back from `.agents/skills-disabled/` without network. |
| `sync-house-skills.py [--check]` | Copies the brain skills marked `.install-as-copy` into `.agents/skills/` and `.claude/skills/`, and removes obsolete copies (the marker of the old organization, `.generated-from-skills-new-project`, counts as a generated copy); `--check` changes nothing and fails if a copy is missing or stale. |
| `check-links.sh` | Read-only: configuration, skill links and copies, then `tools/brain/check-links.py` on each brain, all of them checked even after a failure (a cross-brain link fails; targets missing from `artifacts/` and `repos/` are only reported). Run it after moving files. |
| `doctor.py` | Read-only local diagnosis, without network: required commands, the default brain and the expected brains (`brains` in the default brain's `.data/local-paths.json`), Git state of each one, boundary declared in `.data/brain.json` (fields filled in, effective `remote` and `email` matching the patterns), `.data/*.json` files, input folders, skill configuration (valid layers, changed since the last `update.sh`, skills installed but not adopted, third-party skills not installed, broken or orphaned links, folders of `.agents/skills/` that are neither an enabled third-party skill nor a generated copy) and the artifacts folder (path, inside the Work root or not, symlink status, number of unbacked-up files). Exit code 1 if it finds an error. |
| `setup.py status [--json] \| set <key> <value> \| default <key>` | Setup checklist of this machine, so that an agent asks for what is missing at the start of a conversation. **Settings**, asked and written by an agent: `defaultBrain` and `artifactsDir` in `work-config.local.json` (validated with the rules of `work_config.py`; `defaultBrain` is also done when the rule resolves it, `artifactsDir` when its folder exists), `brains` and `transcripts_dir` (under the home folder) in the default brain's `.data/local-paths.json`, and for each brain `<brain>.owner` (`.data/doctor.json`), `<brain>.scope`, `.description`, `.remote` and `.email` (`.data/brain.json`). `status` gives each one as `done` or `missing`, with its question and its default; exit code 1 while one is missing, 2 when a file cannot be read. `set` validates the answer and writes it; `default` (alias `ignore`) writes the default of a missing setting: `artifacts`, `Documents/Transcripts`, the brains present, the owner of another brain or the Git `user.name`, `personal` for `brain-perso` with a description per scope, the brain's current `origin` URL and commit e-mail; `defaultBrain` (when several brains are present) and the other fields without such a value have no default and cannot be skipped. Writes are atomic and keep the other keys, their order and the layout of the file. **Checks** of what only the owner can do, reported as `owner-action` with the instruction and never blocking: `git` and `uv` (and `npx` when third-party skills are enabled), `bootstrap` (Git hooks of Work and of every brain, `.work-state.json`), `git-identity` (a commit e-mail in Work and every brain, matching the `email` pattern: home configuration and SSH keys, see [`GIT-IDENTITY.md`](GIT-IDENTITY.md)), `artifacts-link` (an `artifactsDir` outside Work and `artifacts/` not linked to it), `tools-env` (`tools/.env` present, checked without reading it, when an enabled own skill names it), `expected-brains`, `transcripts-folder` (a configured folder missing on this machine) and `obsidian` (`.obsidian/` present). Prints no configured value. |
| `hooks/` | Hooks installed by `bootstrap.sh`: `work-pre-commit` (secrets in the staged additions of Work, then the private names of every brain with `check-no-client.py --staged`), `pre-push` (in Work and every brain: `preflight-push.py` on the refs being pushed), `brain-pre-commit` (on a brain's index: misfiled or malformed actions, dead links (except local targets missing from `artifacts/` and `repos/`, only reported) and links to another brain, client names of another brain, secrets), `commit-msg` (Conventional Commits, no AI mention); `check-staged-secrets.py` and `check-commit-msg.py` carry the checks. They validate and never write. `claude-bash-guard.py` is not a Git hook: `.claude/settings.json` runs it before every Bash command of Claude Code to refuse direct `python`, deletions or moves out of `artifacts/` and of the folder set by `artifactsDir` in `work-config.local.json`, read at each run (except into their `archive/`) and Git hook bypasses (`--no-verify`, `core.hooksPath`). `claude-session-start.py` is the SessionStart hook of Claude Code: it prints under 150 words (default brain, brains found, uncommitted and unpushed counts per repository or "all clean", pointers to `brain-state.py map` and `brief`), local Git only with 2 s timeouts, then, when `setup.py` reports missing settings or owner actions, its block (under 500 words): ask the user for each missing setting before any other work, one question at a time, and write the answers with `setup.py set` or `default`; the owner actions on one line. That check runs in a thread and is dropped when it fails or takes more than 1.2 s; nothing is printed about setup when everything is done. The hook always exits 0. |
| `preflight-push.py [--repo DIR] [REMOTE] [--no-ssh] [--no-fetch]` | The checks of [`GIT-IDENTITY.md`](GIT-IDENTITY.md) in one command: no `GIT_SSH*` override, author and SSH key from a boundary file, push URL and e-mail against the brain's `brain.json`, SSH account reported by the host, fast-forward only (no force push, no remote branch deletion). Run by the `pre-push` hook (`--hook`), or by hand before a push. |
| `check-no-client.sh [--staged\|--worktree]` | Scan of this repository (the working tree by default) for the client and person names of every brain and for the employer name (the folder suffix of a brain whose `scope` is not `personal`); run on the staged files by the `work-pre-commit` hook. Certifies nothing. |
| `check-no-client.py --brain DIR --staged\|--worktree` | Scan of a brain against the client names of the other brains of the workspace, except those in the `allow` list of its `.data/brain.json`; run by the `brain-pre-commit` hook on the index. Without `--brain`, same scan as the `.sh`. |
| `gitconfig.example` | Template of `~/.gitconfig` with one identity per trust boundary, to copy and adapt yourself. |
| [`GIT-IDENTITY.md`](GIT-IDENTITY.md) | Git and SSH identity rules per trust boundary (keys, `includeIf`, checking the author, the key and the host key): read it before any remote write or first clone. |

Files generated and ignored by Git: `.agents/` and `.claude/skills/` (skills exposed to the agents), `skills-lock.json` (enabled third-party skills) and `.work-state.json` (fingerprint of the resolved configuration, compared by `doctor.py` and `work_config.py status`).
